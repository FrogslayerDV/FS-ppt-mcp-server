# MCP Resource-Based File Delivery Architecture

## Executive Summary

This architecture document outlines a pure MCP resource-based approach for delivering PowerPoint files from the containerized MCP server to clients. By leveraging the Model Context Protocol's native resource system, we can provide seamless file access without requiring users to manually extract files from Docker containers.

## Problem Statement

PowerPoint files generated by the MCP server are created inside Docker containers, making them inaccessible to users without manual `docker cp` commands. This breaks the seamless experience expected from MCP tools and creates friction in workflows.

## Solution: MCP Resources

MCP Resources provide a protocol-native way to expose data from servers to clients through URI-based access. This approach offers:

- **Protocol Compliance**: Native MCP feature, ensuring compatibility with all MCP-compliant clients
- **Seamless Access**: Files accessible through standard MCP resource URIs
- **No Size Limits**: Resources can handle files of any size efficiently
- **Efficient Memory Usage**: Streaming capabilities prevent memory exhaustion
- **Clean Architecture**: Separation of concerns between file generation and delivery
- **Unified Approach**: Single delivery method for all file sizes

## Architecture Overview

### Resource URI Schema

```
presentation://{server-name}/{presentation-id}/{resource-type}
```

Examples:
- `presentation://ppt-mcp-server/pres_123/file` - The PowerPoint file
- `presentation://ppt-mcp-server/pres_123/metadata` - File metadata
- `presentation://ppt-mcp-server/pres_123/preview` - Thumbnail preview (future)

### Core Components

#### 1. Resource Registry
Maintains mapping between presentation IDs and file paths within the container.

```python
class ResourceRegistry:
    def __init__(self):
        self._resources = {}  # presentation_id -> resource_info
        self._lock = threading.Lock()
    
    def register(self, presentation_id: str, file_path: str, metadata: Dict):
        """Register a new resource"""
        with self._lock:
            self._resources[presentation_id] = {
                "file_path": file_path,
                "created_at": datetime.utcnow(),
                "metadata": metadata,
                "access_count": 0
            }
```

#### 2. Resource Handlers
MCP resource handlers that respond to URI requests.

```python
@app.resource("presentation://*/*")
async def handle_presentation_resource(uri: str) -> Dict:
    """Handle presentation resource requests"""
    parts = uri.split('/')
    presentation_id = parts[-2]
    resource_type = parts[-1]
    
    if resource_type == "file":
        return await get_presentation_file(presentation_id)
    elif resource_type == "metadata":
        return await get_presentation_metadata(presentation_id)
    else:
        raise ResourceNotFoundError(f"Unknown resource type: {resource_type}")
```

#### 3. Enhanced Save Tool
Modified save tool that automatically registers resources.

```python
@app.tool()
def save_presentation_resource(
    file_path: str,
    presentation_id: Optional[str] = None,
    auto_register: bool = True
) -> Dict:
    """Save presentation and register as MCP resource"""
    # Save the file
    saved_path = save_presentation(presentation, file_path)
    
    # Register as resource
    if auto_register:
        resource_uri = register_presentation_resource(
            presentation_id, 
            saved_path
        )
        
    return {
        "status": "success",
        "file_path": saved_path,
        "resource_uri": resource_uri,
        "message": "File saved and available via MCP resource"
    }
```

### Resource Lifecycle Management

#### Registration
- Resources are automatically registered when presentations are saved
- Each resource gets a unique URI based on presentation ID
- Metadata includes creation time, file size, and access statistics

#### Access Control
- Resources are read-only to prevent accidental modifications
- Access is logged for monitoring and cleanup decisions
- Optional TTL (Time To Live) for automatic cleanup

#### Cleanup Strategy
- Configurable retention period (default: 24 hours)
- LRU (Least Recently Used) eviction when storage limit reached
- Manual cleanup tool for immediate removal
- Cleanup runs in background thread to avoid blocking

## Client Integration

### Basic Usage

```python
# Save presentation with resource registration
result = mcp_client.call_tool("save_presentation_resource", {
    "file_path": "quarterly_report.pptx"
})

# Access the file via resource URI
resource_uri = result["resource_uri"]
file_content = mcp_client.read_resource(resource_uri)

# Save locally
with open("local_copy.pptx", "wb") as f:
    f.write(file_content)
```

### Advanced Usage

```python
# List all available presentation resources
resources = mcp_client.call_tool("list_presentation_resources")

# Get metadata without downloading file
metadata = mcp_client.read_resource(
    "presentation://ppt-mcp-server/pres_123/metadata"
)

# Conditional download based on metadata
if metadata["file_size"] < 50_000_000:  # 50MB
    file_content = mcp_client.read_resource(
        metadata["file_uri"]
    )
```

## Configuration

### Environment Variables

```bash
# Resource management settings
RESOURCE_RETENTION_HOURS=24      # How long to keep resources
RESOURCE_MAX_STORAGE_MB=1000     # Maximum storage for resources
RESOURCE_CLEANUP_INTERVAL=3600   # Cleanup check interval (seconds)
RESOURCE_BASE_PATH=/app/resources # Where to store resource files
```

### Docker Compose Configuration

```yaml
version: '3.8'
```
